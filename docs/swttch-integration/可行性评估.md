## 核心结论

可以尝试把本项目的 Claude 交互区域改为它的图形聊天界面，但不能把它作为独立终端控件直接替换 SwiftTerm。两者的交互协议不同。

| 项目 | Claude Picker 当前实现 | Swttch |
| --- | --- | --- |
| 主界面 | SwiftUI / AppKit | React WebView；IDE 内使用 JCEF |
| Claude 通信 | SwiftTerm 启动 zsh，执行交互式 claude，PTY 输入输出 | Node.js 启动 claude -p，使用输入/输出 stream-json |
| 显示 | ANSI/TUI 终端画面 | 结构化消息、工具调用、权限及 diff 卡片 |
| 打开终端 | 内嵌 LocalProcessTerminalView | JetBrains 桥接调用 IDE 的终端；浏览器有独立适配 |
| macOS 嵌入 | 原生 NSView | 可评估 WKWebView + 本地 Node 服务；兼容性尚未实测 |

证据入口：本项目 `Package.swift`、`Sources/ClaudeDeck/TerminalPane.swift`；Swttch 的 `AGENTS.md`、`backend/src/core/claude-process.ts`、`backend/src/core/handlers/openTerminal.ts`、`backend/src/bridge/browser-bridge.ts`、`src/main/kotlin/com/github/yhk1038/claudecodegui/toolwindow/ClaudeCodePanel.kt`。其中 claude-process 构造 `-p --input-format stream-json --output-format stream-json`；openTerminal 将操作交给 bridge，IDE 实现创建终端标签并发送 claude 命令。

## 推荐试验路径

1. 先按上游 CONTRIBUTING.md 的浏览器开发方式运行 backend 与 webview，验证真实 Claude 登录、会话恢复、流式输出、工具调用、权限批准和中断。上游已有浏览器模式，无需先移植 JetBrains 插件。
2. 在独立实验分支添加可切换的 WKWebView 入口，连接仅监听 loopback 的本地服务，沿用上游连接鉴权；先加载完整 Web UI 验证 WebKit 兼容性。
3. 抽象本项目会话接口，分离 SwiftTerm 的 NSView 和进程细节，再接通项目目录与 session ID。避免原生终端和 Node 同时运行同一个 Claude 会话。
4. 验证成功后再裁剪重复的项目/会话导航，接入本项目现有侧栏、设置和 Git 面板，并设计 Node 打包、启动、退出、崩溃恢复和日志策略。

主要改造点：现有 `TerminalSession.send` 注入按键/文本的方式要改为结构化消息和控制请求；OSC 7501/标题忙闲状态改为事件驱动；字体、焦点、复制粘贴、滚动与进程生命周期需要新的视图适配。依赖 PTY 按键的权限模式切换不能直接照搬，斜杠命令在非交互模式下也需要逐项验证。

## 验收标准与边界

- 新建及恢复会话准确落在指定项目，切换项目无串会话。
- 中文输入、粘贴、长消息滚动和后台输出正常。
- 工具权限、diff 接受/拒绝、中断和进程退出状态准确。
- 退出应用不会留下本应用启动的服务和 Claude 子进程。
- 保留 SwiftTerm 切换入口，便于比较和回退。

当前仅确认架构层面存在可实施路径，未证明构建、运行或打包可用。若目标只是改善终端渲染、选中或滚轮行为，这个项目不是对应的替换件；若目标是 Claude 图形聊天体验，则适合作为集成实验。
