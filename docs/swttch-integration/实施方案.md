# Claude 图形交互模式接入方案

## 目标与决策

保留 Claude Picker 的 macOS 外壳、项目/会话侧栏及 Git 面板，把 Claude 交互区域改为 Swttch 的图形聊天界面，并使用其 Node 后端与 Claude CLI 的 stream-json 通信。

先接入完整上游链路，再融合本项目界面。实验期间按设置选择「原生终端」或「图形聊天」，默认保留现有模式。此文为实施设计，不代表已完成兼容性验证。

基线：本项目当前 `codex/git-features`；上游 `/Users/zcl/project/swttch` 的 `3285a17b77919504c66e2ae7d8fbd5cfc4ab8a20`。实施前重新核实分支与工作区，保留现有未跟踪文件；从实际确认的基线创建 `codex/swttch-chat-integration` 实验分支。

## 架构

```text
SwiftUI：项目树 / 会话导航 / Git / 应用设置
    │ 宿主命令、状态事件
    ▼
WKWebView：Swttch React 消息区 / 输入区 / 权限与工具卡片
    │ 上游鉴权通信协议（优先 WebSocket）
    ▼
本地 Node 服务：会话 / 消息 / 工具权限 / 进程管理
    │ stdin/stdout stream-json
    ▼
Claude CLI：每个活动会话独立进程
```

一个应用实例启动一个受管理的 Node 服务，而非每个 WebView 启动一份。后台会话由服务继续维护；关闭或重建 WebView 不等于结束任务。会话切换复用一个 WebView，按会话保存输入草稿、滚动位置和待审批状态。

Swift 负责项目导航及宿主动作；React 负责聊天交互；Node 是运行会话状态的唯一权威来源。Swift 不再与 Node 同时解析或驱动同一个 CLI。原生终端与图形模式不能同时占用同一项目下同一 session ID；切换运行模式需先结束当前运行实例，再恢复会话。

## 本项目改造位置

| 当前入口 | 改造 |
| --- | --- |
| `TerminalPane.swift` 的 `TerminalSession` | 保留为原生实现，通过公共会话接口调用 |
| `main.swift` 的 `panes`、`active`、`open` | 不再把会话类型固定为 TerminalSession；以项目路径和 session ID 关联运行实例 |
| `TerminalPane` 挂载处 | 按交互模式挂载原生终端或 ChatWebView |
| `cycleTo` / `sendShiftTab` | 图形模式走权限模式控制请求，不模拟按键 |
| `setModel` / `setEffort` / `toggleFast` | 接入已验证的上游控制能力；不支持时明确禁用相应入口 |
| 标题、busy、awayOutput、退出回调 | 图形模式由结构化事件更新；区分运行中、等待权限、空闲、错误、已退出 |
| `scripts/build-app.sh` | 加入 Web 静态资源、Node 后端产物及独立运行时打包 |

建议新增 `ChatWebView.swift`、`ChatBackendManager.swift`、`ChatSession.swift`、`ChatHostBridge.swift`。名称是建议，不预设必须新建目录或重构整个 main.swift。

公共会话能力只覆盖实际调用：打开/恢复、发送消息、中断、结束、切换前后台、订阅状态。字体与焦点由各视图适配。PTY 的 pid、view、按键序列留在原生实现，避免让图形模式假装成终端。

## 上游复用边界

复用 backend 与 webview，固定上游版本并保留本地补丁记录。Kotlin/JCEF 层不进入 macOS 应用。首次实验直接使用独立源码目录；进入可复现构建阶段再确定 vendor 或子模块管理方式，避免依赖开发机绝对路径。

新增「嵌入宿主模式」：隐藏上游重复的项目/会话导航，接受 Swift 发出的打开会话、主题、字体和焦点命令，回传会话状态与标题。优先用现有协议扩展，避免创建第二套消息/权限业务逻辑。

WKScriptMessageHandler 仅提供有限的宿主操作：打开文件、选文件、剪贴板和导航等。聊天消息及权限请求沿用上游前后端链路。桥接消息需有版本、请求 ID 和会话身份；异步结果必须核对身份，防止切换会话后更新错误的界面。

文件与 diff 初期使用上游浏览器模式现有能力；涉及 JetBrains API 的部分逐项替换。实验期可以保留 Web diff 卡片，原生 Git 面板仍只负责 Git 工作流。不要把 Git 暂存/提交和 Claude 工具权限批准绑定为一个操作。

## 分阶段交付

### 第一阶段：运行上游，验证协议可用

按 CONTRIBUTING.md 安装依赖，使用 `scripts/build.sh be-dev` 和 `wv-dev` 启动。使用专门测试目录及独立 Claude 会话，避免在生产项目中验证编辑权限。

验证：当前已登录 CLI 的发现、指定 cwd、新建/恢复会话、中文流式消息、工具审批/拒绝、diff、中断及退出；盘点模型、effort、fast 和斜杠命令支持范围。明确 CLI 最低兼容版本和实际启动参数。

交付：可运行的上游实例、兼容性记录与阻塞项。若基础链路不可用，先定位问题，不进入 UI 融合。

### 第二阶段：在 macOS 内完成最小真实闭环

加入可切换的 WKWebView 入口及 BackendManager；先允许完整上游 UI 显示。由应用启动服务，等待明确的就绪信号后加载页面；启动失败可重试并切回原生终端。用单会话验证 WebKit 的连接、输入法、剪贴板、文件选择和长消息渲染。

交付：本项目里能真实发送消息、审批工具、中断和恢复一个会话。浏览器可运行不等于 WKWebView 验证通过，必须在应用内验证。

### 第三阶段：接通现有侧栏与多会话

抽象会话接口并接入现有项目树。隐藏 Web 端重复导航，项目和 session ID 从 Swift 传入。运行状态、等待审批、未读标记从 Node 回传；保留每会话草稿、滚动位置及后台运行。会话历史沿用 CLI/上游持久化机制，Picker 仅存导航与显示偏好，不另建消息历史数据库。

交付：连续切换两个项目及多个会话，消息、输入草稿、权限弹窗和未读状态均不串线；重启应用后可恢复历史。原生终端已存在的历史会话需实测恢复兼容性，不直接修改历史文件格式。

### 第四阶段：设置、宿主能力与打包

接入模型/权限模式等已验证控制接口，适配文件打开和 diff；补齐主题、字体及快捷键。把静态资源、后端和所需 Node 运行时打入 app，目标机无需安装开发工具或全局 Node。Claude CLI 仍作为外部依赖，安装、认证与找不到可执行文件的状态需要清晰呈现。

交付：Apple Silicon 安装包，在不依赖源码目录、node_modules 和全局 Node 的环境下启动；路径含空格也可工作。检查运行时、后端产物的签名和许可清单。

## 生命周期与本地服务

- 服务只绑定 loopback，采用动态端口与每次启动的新 token，沿用或适配上游鉴权及 Origin 校验；不要在日志记录 token 和认证信息。
- 运行时资源只读放在 app 内，日志与可写状态进入应用支持目录。
- 启动时检查 CLI 路径、Node 服务状态及协议版本；从 Finder 启动时不能假定能继承终端 PATH。
- 网页连接断开与 CLI 退出分别处理。重连先读取服务当前快照，再衔接事件；若上游缺少可靠重放机制，须补齐或显式标注缺口。
- 服务崩溃不自动重发上一次用户消息；展示错误并允许恢复，避免重复执行工具。
- 退出应用时，结束应用拥有的会话子进程和 Node 服务；使用受控超时兜底，不误杀系统内其他 Claude 进程。关闭聊天面板、停止会话、退出应用三个动作分别定义。

## 验证与采用标准

以真实行为为依据：新建、恢复、中文输入、图片/文件输入、多会话切换、工具批准/拒绝、中断、CLI 异常退出、Node 崩溃、WebView 重建、应用退出及离线启动。协议适配和生命周期逻辑加入必要自动化测试；视觉和输入法在 WKWebView 中人工检查。上游修改遵循其 AGENTS.md 的测试要求。

所有核心闭环和安装包验收通过后，才考虑把图形模式作为默认；此前维持实验开关和原生终端回退。采用门槛包括：会话不串线、权限可正常回答、恢复不丢历史、不重复发送消息、退出无孤儿进程。

## 成本与待验证项

这是交互层和运行链路迁移，不是仅替换视图。工作量集中在多会话同步、WebKit 兼容性、宿主桥接与独立打包。暂不给缺乏实测依据的工期承诺，完成第一、二阶段后再估算剩余工作。

已知约束：上游根许可证为 AGPL-3.0；选择复制/修改并分发其代码时，应按实际集成方式核对许可和对应源码提供要求。尚待验证：上游当前版本构建、现用 Claude CLI 的协议兼容性、历史会话恢复、WKWebView 功能、Node 嵌入分发和性能。
