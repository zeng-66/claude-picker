# TAPD 融合方案

## 产品目标

在 Claude Picker 中完成「查看 TAPD 待办 → 读取需求及附件 → 关联代码仓库 → 创建开发任务 → 图形聊天开发 → 查看验证与 Git 结果 → 回填 TAPD」的闭环。

TAPD 是业务需求、负责人、迭代、排期及业务状态的来源；本地任务层管理 AI 执行、worktree、会话和证据；Swttch 提供交互界面与 Claude 通信。三个系统使用关联 ID，不共用一个状态字段。

本方案依据当前可发现的 TAPD MCP 工具能力制定，尚未调用业务查询或写入接口，也未验证独立桌面应用的认证接入。

## 界面与流程

1. 设置中配置 TAPD 连接与「TAPD workspace → 本地仓库」映射。一个 workspace 可映射多个仓库，一个需求也可派生多个仓库开发任务；存在多候选时由用户选择。
2. 工作台增加 TAPD 入口，展示项目、我的待办、迭代、需求与缺陷。明确标注待办及最后同步时间，支持粘贴 TAPD 链接定位。
3. 详情展示描述、附件/图片、评论、关联任务、负责人、排期和当前状态。读取失败或无权限的附件明确列出，不能标成已理解。
4. 「开始开发」生成任务准备页：来源 ID、需求版本快照、验收条件、目标仓库、基线、拟建分支和 worktree。缺少验收条件或有阻塞歧义时进入待澄清。
5. 创建本地任务后，在现有图形聊天区开发；右侧任务详情持续显示 TAPD 来源、变更、测试结果和待决问题。
6. 交付时生成回填草稿，展示目标对象和具体修改内容；用户可直接批准此次回填，也可事先配置明确的自动回填规则。写入成功后回读核实并记录凭据。

「开始开发」授权建立当前任务和执行本地开发，不自动等于批准发送评论、修改负责人、填写工时、关闭需求或合并代码。具体写入权限由用户操作或显式规则授予。

## 架构边界

```text
TAPD 适配器：查询、字段/工作流发现、附件读取、授权写入
      ↓ 规范化来源事件/需求快照
任务协调器：去重、关联、准备、排队、恢复、证据
      ↓
仓库/worktree + Claude 执行器 + Swttch 图形交互
      ↓
回填队列：草稿 → 授权 → 写入 → 回读 → 成功/冲突/待核实
```

TAPD 适配器放在本地 Node 服务中；WebView 不持有长期凭据，Swift 外壳负责 Keychain 存储或安全授权入口。适配器调用固定的领域方法，不允许模型任意拼 API 或绕过写入规则。

本次聊天环境已有 TAPD MCP，能证明集成所需操作可被工具表达，但桌面应用不能直接继承 Codex 内的工具或凭据。实现时须建立应用自己的 MCP 客户端连接，或接入 TAPD 官方 API。MCP 与 API 共用同一适配器接口；优先验证现有 MCP 服务是否支持独立连接和所需认证，避免同时开发两条链路。

## 数据模型与状态

- 来源身份：`workspace_id + entity_type + entity_id`；必须保留完整 ID，展示短号时不得把短号作为唯一键。
- 来源快照：标题、描述、负责人、迭代、排期、状态、更新时间、正文 hash、附件读取结果。
- 本地任务：sourceRef、repo、branch、worktree、session、执行记录及验证证据。一条需求可关联多个任务，不能把需求唯一绑定到单一会话。
- 写入记录：目标对象、操作类型、字段差异/评论正文、授权范围、幂等键、执行结果和回读结果。

本地执行状态使用待澄清、排队、执行中、待回答、待审阅、失败、停止和完成等状态；TAPD 状态单独展示。AI 结束回合、代码提交、PR 合并、测试通过都不能单独推导需求已完成、已部署或已上线。

状态回填按各 workspace 的工作流映射配置。先查询状态定义与允许流转，不把中文显示名称或某个项目的状态代码硬编码到所有项目。需求、任务、缺陷分别处理。

## 同步与变更处理

第一版使用按需读取、手动刷新和有界轮询，尚未核实 webhook 可用性，不能以 webhook 为前提。支持分页、限流退避和断线重试；无变化时不触发 AI 会话。

同一来源重复导入时返回已有任务或让用户选择新建执行轮次；评论/描述更新保存增量并提示。需求实质变更时重新核对验收条件，不在用户无感知时重启开发或覆盖当前上下文。

事件幂等键优先使用上游事件标识，否则组合来源身份、修改时间与内容 hash。写入前重新读取目标字段；已被他人修改则展示冲突。若 API 不支持条件更新，说明这是尽力冲突检查，不能保证原子 compare-and-set。

超时后写入结果未知时先核实，不能直接重发评论。将评论作为独立动作，避免重复回填。附件下载链接可能短期有效，使用前重新获取，不能当成长期文档地址。

## 回填内容与权限

首版支持生成并批准回填：实现摘要、关联 commit/PR、验证结果、未解决问题。状态流转单独授权。无证据的工时、完成时间、部署和上线结果不填写、不推断。

认证按只读与允许写入能力区分；应用隐藏按钮不能替代后端授权。凭据不进入仓库、任务提示词、WebView localStorage 或普通日志。来源文本是需求资料，不能用来扩大工具权限或改变宿主安全策略。

企业项目可加载各仓库现有分支/交付规范。例如方果、蓝马和 lm-global 的实际流程应分别适配，不能把 Claude Picker 的分支规则直接套到所有仓库。第一版只建关联和草稿，不改现有企业项目规范。

## 能力映射与阶段

当前工具目录提供：参与项目/待办、需求与任务、缺陷、迭代、评论、附件和图片、字段及工作流查询，以及评论/状态等写入操作。后续按目标 workspace 验证权限和返回格式，不能仅凭工具存在宣布接口可用。

1. 只读入口：连接、workspace/仓库映射、待办列表、需求详情、附件读取状态、手动导入。
2. 开发关联：需求快照、任务/worktree/会话绑定、需求变更提示、状态分离。
3. 受控回填：草稿预览、授权范围、字段冲突检查、去重和写后回读。
4. 自动化：在明确规则下轮询触发、后台任务及结果通知。首版不自动接受所有新需求，也不默认监听全部企业项目。

建议顺序：先验证 Swttch 应用内单会话，同时完成 TAPD 只读导入；之后将 TAPD 来源接入任务层，再添加多任务调度及回填。无需等待完整 SuperAgent 移植才能提供 TAPD 价值。

## 验收

覆盖同短号不同 workspace、分页、无权限、附件过期、多仓库选择、重复导入、会话切换、来源变更、非法状态流转、评论超时结果未知、凭据失效和应用重启恢复。完成任务后必须能回溯到唯一来源与具体代码/验证证据。
