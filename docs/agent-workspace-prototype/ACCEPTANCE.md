# 验收计划与故障场景

对应 [开发说明](DEVELOPMENT.md) 和 [交互规格](INTERACTIONS.md)。本文件定义正式实现的验收目标，不是已经执行的测试报告。

## 1. 验证分层

| 层级 | 检查对象 | 适用验证 |
| --- | --- | --- |
| 领域 | Work 状态、幂等、版本、归属、排队 | 重点单元/集成测试，使用真实 SQLite 事务验证关键不变量 |
| 适配器 | CLI、Git、TAPD、WorkBuddy | 合约测试及受控环境联调，不把 mock 响应当外部能力证据 |
| 宿主 | WKWebView、进程、路径与桥接 | macOS 应用内集成验证；浏览器通过不能替代 |
| UI | 输入、焦点、导航、草稿、等待与错误 | 行为测试及人工检查；视觉/输入法在目标环境检查 |
| 安装包 | 资源、运行时、签名、迁移与退出 | 脱离源码目录及全局 Node 的安装测试 |

测试环境使用专门仓库、独立会话及允许的 TAPD/企业微信测试对象。涉及真实评论、回复、提交等操作须在明确授权的测试范围内进行。不得为了验证读操作而顺带回写。

## 2. 核心验收场景

### 2.1 布局、项目与会话

| ID | 操作/前提 | 必须观察到 |
| --- | --- | --- |
| UI-01 | 打开 A/B/C、切主导航 | 原活动 Work、会话草稿和后台执行保持；布局不创造领域事件 |
| UI-02 | 两个项目分别有不同草稿并来回切换 | 每份草稿只属于原 Session，不出现串稿 |
| UI-03 | 收起对话、拖浮卡、恢复 | 文本/附件/选择状态保留；始终有可见恢复入口 |
| UI-04 | 窗口在桌面宽度与较窄宽度间调整 | 无不可达按钮；输入区和主操作可用；浮卡回到可见范围 |
| UI-05 | 拖动详情分隔条，再关闭并恢复详情 | 宽度按约束保留；不影响当前 Run |
| UI-06 | 项目下 8 个会话且有置顶项 | 初始最多 5 条，展开/收起语义正确；项目彼此独立 |
| UI-07 | 全局搜索后打开另一 Work，再返回 | 打开正确项目/Work，旧会话草稿保留 |
| UI-08 | 中文输入法组合状态下按 Enter/快捷键 | 不误发半成品消息；键盘和输入规则一致 |
| UI-09 | 用键盘进入/关闭弹窗及菜单 | 焦点可见、无焦点逃逸、关闭返回触发处 |
| UI-10 | 搜索返回顺序与请求顺序相反 | 仅最新查询更新列表，原选中身份可检查 |

### 2.2 Work 与执行状态

| ID | 操作/前提 | 必须观察到 |
| --- | --- | --- |
| WK-01 | 创建有唯一项目的本地 Work | 获得持久 ID、正确目录和来源；不是只添加 UI 卡片 |
| WK-02 | “创建后启动”未勾选 | Work 可见但调度器不启动，明确等待启动授权 |
| WK-03 | 并发上限 2，同时启动第 3 个 | 第 3 个 queued，不创建超额执行进程 |
| WK-04 | worktree 准备失败 | 记录失败及输出，当前 Run failed；重试保留旧证据 |
| WK-05 | Work A 在运行，用户切到 B，A 完成 | A 进入待审阅，B 不变；未读/关注标记归 A |
| WK-06 | 连点启动或重复发送同一启动命令 | 至多一个当前 Run，不重复建目录或进程 |
| WK-07 | 中断正在生成的 Run | 输出保留，最终显示 interrupted；其他 Work 不受影响 |
| WK-08 | 取消 Work 后迟到工具/消息事件到达 | 不重新启动、不修改已结束决策；事件可追踪 |
| WK-09 | 收到需人答复的业务问题 | Work waiting_user，问题 ID 与目标明确，其他任务可推进 |
| WK-10 | 对已回答/过期 Attention 再次答复 | 返回已处理/过期，不能重复恢复或跨轮批准 |
| WK-11 | 接受结果后外部汇报失败 | Work completed，Delivery failed；有独立重试入口 |
| WK-12 | 已完成 Work 收到新范围需求 | 新 Run 或新 Work 需明确建立，保留旧轮验收事实 |

### 2.3 图形 CLI 与原生回退

| ID | 操作/前提 | 必须观察到 |
| --- | --- | --- |
| CLI-01 | Finder 启动应用，CLI 不在普通 PATH | 按宿主规则发现 CLI，或给明确安装/路径错误 |
| CLI-02 | 发送消息且后端 ready 尚未到达 | 不声称已发送，不丢稿；就绪后按消息状态发送 |
| CLI-03 | 流式输出在多字节字符中切包 | 中文无乱码；消息 ID 与顺序正确 |
| CLI-04 | 工具请求批准/拒绝 | 实际控制请求收到正确答案，拒绝后不擅自执行 |
| CLI-05 | 模型/权限/effort/fast 不支持或切换失败 | 禁用或报错并保留旧值，UI 不假成功 |
| CLI-06 | 已有原生 Session，切图形后端 | 不能双持有同一 CLI 会话；迁移/重开行为明确 |
| CLI-07 | WebView 重新加载但执行进程还活着 | 重连恢复快照，不重复发上一条消息，不假死/假忙 |
| CLI-08 | 用户阅读历史时收到输出 | 保持滚动锚点并出现新消息入口 |
| CLI-09 | CLI 退出但本地服务仍在 | 正确 Run 记录退出码和状态，服务连接状态不混为执行状态 |

### 2.4 TAPD

| ID | 操作/前提 | 必须观察到 |
| --- | --- | --- |
| TP-01 | 打开我的待办并筛选两个 workspace | 身份、项目和待办语义正确；分页无重复/遗漏 |
| TP-02 | 短号相同但 workspace 或实体类型不同 | 完整 TapdRef 可区分，不能关联错对象 |
| TP-03 | 需求附件权限失败/链接失效 | 显示未读取与原因；有效期失效重取，不假装已读 |
| TP-04 | 导入同一需求两次或请求超时后重试 | 先返回已有关联/确认新一轮，不重复执行 |
| TP-05 | 在开发期间修改远端需求范围 | 本地显示差异与影响，等待确认，不暗中覆盖目标 |
| TP-06 | 预览评论后关闭 | 远端没有变化；草稿可恢复 |
| TP-07 | 只确认添加评论 | 工作流状态、工时和上线字段不随之改变 |
| TP-08 | 写前字段被他人修改 | 冲突可见，不盲目覆盖；无条件更新能力时说明限制 |
| TP-09 | 写入超时但服务端实际成功 | 先核对，再决定重试；不重复评论 |
| TP-10 | 状态迁移不被当前工作流允许 | 不显示成功，保留原状态并说明可用流转 |
| TP-11 | 独立企业微信 Work 无 TapdRef | 不出现 `#null`、TAPD 回填或无关需求详情 |

### 2.5 企业微信、WorkBuddy 与自动工作目录

| ID | 操作/前提 | 必须观察到 |
| --- | --- | --- |
| WB-01 | 进入企业微信机器人设置 | 没有群聊项目映射、固定工作目录、必须先配项目的提示 |
| WB-02 | 消息显式指向一个已知项目 | 自动判定并展示对应目录；创建目标不依赖手选下拉 |
| WB-03 | 同群先聊项目 A，再显式发项目 B 的新任务 | 新 Work 归 B，不被 A 的会话残留强行覆盖 |
| WB-04 | 消息未指定目标且上下文不足 | 在原对话追问，不静默选择最近项目或群默认目录 |
| WB-05 | 两个项目重名/消息涉及多项目 | 保持待澄清，不因第一个匹配而启动 |
| WB-06 | 人回复澄清问题 | 只完善该意图，重新解析；不生成固定群聊映射 |
| WB-07 | 回答来自另一会话/不允许的成员 | 不被当作原任务的批准或目录确认 |
| WB-08 | 消息是普通问答、非执行请求 | WorkBuddy 可回答，但不产生空 Work |
| WB-09 | 同一消息事件重复投递/重连重放 | 最多创建一个 Work，创建回执也去重 |
| WB-10 | 同一人同群同时有两个澄清中的需求 | 回复按意图/问题关联；不明确时再次询问归属 |
| WB-11 | 模型返回未知路径、未登记项目或跨目录符号链接 | 宿主拒绝访问或请求明确登记；不扩大文件权限 |
| WB-12 | 目录识别后实际目录被移走/仓库身份变化 | 创建/启动前再次校验，停止并报错，不切其他目录 |
| WB-13 | 从微信创建 Work，再从项目打开 | Work 编号、来源、项目、Session、Run 一致；TAPD 未新增对象 |
| WB-14 | Work 产生需要人处理的问题 | WorkBuddy 向正确原会话投递；回答进入正确 Attention |
| WB-15 | 完成审阅后交付 | 原会话收到对应 Work 结果；已发送有实际回执 |
| WB-16 | 汇报发送结果未知 | Delivery unknown，先核对；不自动刷群或宣称已送达 |
| WB-17 | 关闭机器人接收 | 不创建新消息来源 Work，已接受 Work 保留且仍可查看/控制 |
| WB-18 | 新意图开始，上一意图曾明确过目录 | 不把旧澄清结果无条件复用；按本次消息判定 |

注：当前 H5 可演示 WB-01、WB-02 的名称匹配、WB-04、WB-06、WB-13 及模拟 WB-15；这些不证明真实接口或语义识别实现。

### 2.6 Git、证据与审阅

| ID | 操作/前提 | 必须观察到 |
| --- | --- | --- |
| GT-01 | 两个 Work 的不同 worktree 分别暂存/提交 | 状态与提交信息隔离，不操作主仓库的其他变更 |
| GT-02 | 无暂存内容、空提交信息、Hook 失败 | 按具体原因禁用或报错；草稿保留，无假 SHA |
| GT-03 | 审阅后代码再次变化 | 旧审阅立即失效，不能继续当作当前代码批准 |
| GT-04 | 测试通过后新增修改 | 验证结果标为对应旧版本，要求适当重跑 |
| GT-05 | 二进制、重命名、已删除、超大文件 | 文件类型和可用审阅方式正确，无固定示例冒充 |
| GT-06 | 普通提交操作 | 只提交当前目标，不自动 push/merge/deploy 或写 TAPD 完成 |

### 2.7 持久化、故障与安装

| ID | 操作/前提 | 必须观察到 |
| --- | --- | --- |
| OP-01 | 数据库事务中途崩溃 | 无半个 Work、无失去来源的 Run，恢复可判定 |
| OP-02 | 本地服务重启时已有 running Work | 校验实际进程/会话，保留证据并恢复或标 interrupted；不盲重发 |
| OP-03 | 两个服务实例争抢同一状态目录 | 只有一个 owner，其他实例不能并发调度相同 Run |
| OP-04 | 退出应用并选择结束自有执行 | 自有服务/子进程退出；不误杀其他 Claude 进程 |
| OP-05 | 程序退出有超时未结束子进程 | 留下明确清理结果/失败提示，不隐藏僵尸状态 |
| OP-06 | 数据库升级失败或旧版本打开新库 | 不破坏既有数据，保留备份及明确恢复方式 |
| OP-07 | app 放到路径含空格的位置，系统无全局 Node | 安装包自带运行时与资源正常工作 |
| OP-08 | 外部页面尝试调用桥接/本机其他网页连接服务 | 认证、Origin 与桥接来源检查拒绝 |
| OP-09 | 日志、错误、导出诊断包 | 可定位关联 ID，但不泄露 token、敏感消息或凭据 |
| OP-10 | 服务断线重连、事件发生间隙 | 恢复快照/游标，不漏状态、不重复应用消息 |

## 3. 关键端到端验收脚本

### E2E-A：企业微信独立 Work

1. 连接经过验证的测试机器人，准备两个本地项目；不配置群聊映射。
2. 在群中明确请求处理项目 A 的目标，核对自动目录判断与 Work 回执。
3. 在同群明确请求项目 B 的另一目标，核对两份 Work 分别归属。
4. 两任务执行时切换会话，回答 A 的业务问题，验证 B 不被恢复或改状态。
5. 审阅 A 的当前版本，确认 Work 结果并投递到原会话。
6. 重放 A 的来源事件，验证不新增 Work/Run，不重复结果发送。
7. 查看 TAPD，确认没有由这个独立来源流程创建的需求/任务。

### E2E-B：目录歧义

1. 发“帮我优化搜索”，不提供可唯一识别的上下文。
2. 机器人在原对话询问目标，不出现执行进程或新 worktree。
3. 另一成员在其他对话回复项目名，原意图不得被确定。
4. 原发起人对原问题补充目标，宿主校验真实项目目录后创建 Work。
5. 紧接着发另一条无上下文需求，不能把上一轮目标当固定映射。

### E2E-C：TAPD 到 Work 到回填

1. 读取真实测试待办、完整需求及附件读取结果，保存来源快照。
2. 导入 Work，启动对应仓库 worktree，核对 TAPD 状态未被顺带修改。
3. 执行、验证、审阅并创建提交，证据对应同一代码版本。
4. 修改回填草稿并确认评论，回读成功；状态与工时保持不变。
5. 模拟网络超时并核对幂等处理，不产生重复评论。

### E2E-D：崩溃恢复

1. 一份 Work running，另一份 waiting_user，第三份 waiting_review。
2. 重启服务与 WebView；分别验证执行状态、未答问题、草稿及审阅版本。
3. 恢复前不自动重发最后消息，也不把所有 Work 改成 running。
4. 回答旧版本问题或接受过期 diff，观察拒绝及可恢复入口。

## 4. 测试报告模板

每次正式实现交付至少记录：

| 字段 | 必填内容 |
| --- | --- |
| 验证版本 | 本项目 SHA、上游固定版本、CLI/Node/macOS 版本 |
| 验证对象 | 实际执行的场景 ID，范围与未覆盖项 |
| 真实副作用 | 测试仓库/来源对象及已授权操作，不包含凭据 |
| 证据 | 命令、退出码、关联代码版本、截图或适当日志位置 |
| 结果 | 通过/失败/未执行/被阻塞，不混用 |
| 清理 | 测试进程、worktree、外部消息和测试记录的保留/清理情况 |

不得把“编译通过”“mock 流程通过”“UI 显示成功”写成全链路通过。真实接入尚未具备时明确列为未执行。
