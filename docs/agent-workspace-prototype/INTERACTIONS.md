# 交互与按钮规格

对应 [开发说明](DEVELOPMENT.md)。本表中的 `action` 来自当前 `src.js`，只作定位，不等于正式后端接口。

## 1. 通用交互规则

- 按钮须有可访问名称，图标不代替名称。禁用要能看出原因；读取失败、无权限与空数据使用不同提示。
- 会产生副作用的按钮：请求期间防重复提交，明确“已接受/执行中/成功/失败/结果未知”；关闭弹窗不假装撤销已被服务接受的命令。
- 纯导航和视图切换不修改领域状态，不取消后台任务。异步更新核验目标身份。
- 表单必填字段内联显示错误，保留用户输入，不能只弹瞬时 toast。连接操作不得把凭据写入日志。
- 草稿按 Session 保存，提交信息按 workspace 保存；未发送、发送失败、正在发送、已送达分别展示。
- 弹窗支持 Escape 和关闭按钮，焦点进入弹窗且被约束，关闭后回到触发入口；有未保存修改时按表单规则处理。
- 成功 toast 不能代替持久状态。涉及投递、执行和连接的最终状态必须可回看。
- 不同来源共用 Work 能力，但不混用外部编号、业务状态和回填入口。

## 2. 标题栏、导航与项目会话树

| action | 入口 | 触发与成功表现 | 正式实现的边界/失败表现 |
| --- | --- | --- | --- |
| `sidebar` | 左栏开关 | 收起/展开项目树；记住宽度及展开状态 | 无活动项目也可使用；不能连带退出会话 |
| `project-menu` | 当前项目名 | 打开项目选择器，显示当前项目及可访问项目 | 加载失败可重试；当前项目不可访问要保留标记 |
| `choose-project` | 项目选项 | 切换项目上下文，恢复该项目最近活动会话或显示空态 | 不自动切分支、不移动已有 Work；后台任务继续 |
| `page` | 工作空间/TAPD/任务/变更、侧栏待办/Work 中心 | 切主区域，保留当前 Work；TAPD 页保留筛选与选中对象 | 变更页依据当前 workspace，无仓库则显示原因 |
| `collapse` | 项目折叠箭头 | 每个项目独立展开/收起，不改变活动 Session | 点项目会话和点折叠箭头行为区分；可用键盘展开 |
| `task` | 项目下会话或 Work 卡片 | 打开对应 Work/Session，恢复草稿、活动 Run、滚动锚点和上下文 | 会话不可恢复时保留 Work 并给恢复入口；不回退到其他项目 |
| `new-session` | 项目树新建入口 | 新建普通会话，默认当前项目，尚未执行前允许讨论 | 不添加多余常驻“新建”行；右键亦可新建；不是每次聊天都创建 Work |
| `new-task` | 新建 Work、看板列加号 | 创建本地 Work，收集目标、项目与执行范围 | 本地入口允许用户选择项目；企业微信自动判目录不使用该表单；队列满则排队 |
| `create-local` | 本地会话/Work 的“创建” | 校验名称和项目；按入口创建实体，再跳转 | 名称空/目录失效不创建；幂等处理连点；原型目前两入口共用模拟任务，生产需拆语义 |
| `history` | 展开其余会话 | 原 App 语义为展开剩余会话并可收起，优先显示置顶/最近项 | 当前原型为历史弹窗演示，不应把弹窗当成最终树行为 |
| `history-open` | 历史会话条目 | 恢复原 Session/上下文，而非把标题塞入当前输入框 | 原型只把文字放入草稿；正式恢复失败允许查看历史，不伪装恢复成功 |
| `search` | 搜索图标/⌘K | 全局搜索项目、Work、会话及可见 TAPD 编号 | 正式接口分页/取消旧查询；无结果显示空态 |
| `search-task` | 搜索或任务列表结果 | 关闭搜索，进入匹配对象 | 完整身份查找，避免不同项目短编号重名；保留原会话草稿 |

补充：项目/会话右键需提供适用的新建、置顶、重命名、归档、结束会话和打开目录。拖动排序、置顶及最多先显示 5 条是继承目标；当前原型未全部具备。归档不等于取消 Work，删除本地导航项不删除 CLI 历史或 worktree；有运行中任务时不能静默清理执行目录。

原型侧栏头像当前仅展示，正式版如果开放账号信息应单独定义；不把不可操作头像表现成可点击按钮。项目路径、分支路径被截断时可查看完整值。标题栏分支当前为上下文展示，正式需要切换时复用版本校验的 Git 操作，不能仅改显示文本。

### 3.1 无 action 属性的输入行为

| 控件 | 正式行为 |
| --- | --- |
| 消息文本框 `message` | 每个 Session 独立草稿，输入法组合期间不触发发送；不因切布局丢稿 |
| 发送按钮 / `message-form` | 空白内容且无有效附件时禁用；本地 messageId 幂等；发送中显示状态，失败保留重试入口 |
| ⌘Enter | 编辑器中提交当前内容，避免与输入法候选确认冲突；原生菜单快捷键一致 |
| 默认 Enter | 按应用消息设置换行；发送快捷键在输入区有可发现提示 |
| 问题单选项 | 正式不得预选涉及业务含义的默认答案；选择只更新草稿，点确认才答复 |
| 上下文占用 | 显示真实模型限制与使用量，悬停有已用/总量；未知时显示未知，不伪造 16% |
| 文件/工具代码块 | 可复制，长行横向滚动，错误和运行状态可读；打开链接经宿主验证 |
| 新消息 | 正在阅读历史时保持锚点；在底部时跟随；切换会话恢复各自位置 |

## 4. Work 看板、详情与活动

| action | 入口 | 触发与成功表现 | 正式实现的边界/失败表现 |
| --- | --- | --- | --- |
| `board-view` | 看板 | 分组显示 queued/running/waiting_user/waiting_review 等 | 原型点击仅 toast；正式是实际视图切换 |
| `task-list` | 列表 | 相同筛选下显示 Work 列表，支持状态与项目定位 | 原型为弹窗；正式是否内联由选定布局决定，不能遗漏失败/取消/已完成项 |
| `file` | 变更文件条目 | 打开对应文件的真实 diff，保持 workspace 与选中路径 | 文件被删除/二进制/超大分别呈现；不能换名字但展示另一个固定文件 |
| `workspace-return` | 返回对话 | 回到同 Work 当前 Session | 不重启、不改变审阅结果 |

看板列标题、数量、执行容量均来自领域状态，不用列表长度假装进程数量。waiting_user 与 waiting_review 需要明确关注标记；失败、取消、已完成在过滤器或历史中可达。原型“所有项目”与卡片省略号目前为展示，没有真实筛选/菜单；正式版要实现或移除交互外观。卡片不默认通过拖动改变状态：运行/完成不能拖出来，必须有对应事实。

详情：企业微信 Work 展示 Work 编号、项目、发起人、WorkBuddy 原始对话、Run、工作树和交付状态；TAPD 来源额外展示独立业务状态。无关联时不显示 `TAPD #null` 或跳转到其他需求。活动展示真实事件时间、发起者和重试轮次，原型静态时间不复用。

| `save-mapping` | 保存映射 | 校验已登记的项目/目录后持久化配置 | 原型只 toast；正式需回读，重复关系不重复保存 |

### 5.1 字段和上下文

- `tapd-search`：搜索标题/编号，保留输入焦点与光标；防抖查询并忽略过期结果，Enter 可立即搜索。
- 导入名称：默认来源标题，可修改本地 Work 名称，不能改远端标题。
- 仓库：TAPD 可多候选；未唯一确定则选择/澄清，禁止默认列表第一项后静默执行。
- “创建后启动”：仅表达启动意图，不绕过并发和权限；未勾选仍创建 queued Work，但需额外的启动许可标记，调度器不得自动拾取未授权项。
- 需求描述富文本需净化，图片/附件各自显示读取状态与失败原因；评论不能被当成宿主系统指令。
- 负责人、迭代、排期以当前 TAPD 为准，无值展示 `—` 或 `待 TAPD 排期`。

## 6. Git 暂存、提交、审阅和回填

| action | 入口 | 触发与成功表现 | 正式实现的边界/失败表现 |
| --- | --- | --- | --- |
| `stage` | 暂存全部/取消暂存 | 将当前 workspace 的已明确文件写入 index 或取消暂存，并回读 | 正式 UI 拆成明确动词，不能用全局布尔翻转；并发文件更新提示重新读取 |
| `commit` | 创建提交 | 使用当前 index 与非空消息提交，返回 SHA | 无暂存变更禁用；Hook 失败、身份缺失、冲突等保留消息；不自动 push/merge |
| `approve-review` | 确认变更 | 记录对当前 Run 及当前 diff/commit 版本的审阅 | 代码变化使旧批准失效；不能只记 `true` |
| `writeback` | 预览 TAPD 回填 / 预览 Work 汇报 | 根据来源生成对应草稿，不产生外部副作用 | 企业微信独立 Work 不打开 TAPD 表单；缺证据明确标注 |
| `confirm-writeback` | 模拟确认回填（正式“确认回填”） | 当前 TAPD 草稿校验后入队，成功回读再显示已回填 | 未审阅/空文/版本变化禁用；超时未知先核对，避免重复评论；不把添加评论当完成需求 |
| `work-delivered` | 模拟交付并回复（正式“交付并汇报”） | 确认 Work 结果及回复目标，交给 WorkBuddy 投递 | 结果投递状态独立，失败或未知可处理；未收到回执不显示已发送 |

文本编辑框 `commit-msg` 按 workspace 保留。草稿 `writeback-text` / `work-delivery-text` 按 Work/目标保存，关闭时有未保存内容应可恢复。展示生成依据与将要发送的目标，内容不会随后台事件悄悄覆盖用户编辑。

验证区：各检查展示实际命令、环境、起止时间、退出码及关联代码版本；“未运行”与“失败”不同。不支持的文件预览应给明确说明，不能展示固定示例来冒充当前仓库。

生产前的额外 Git 能力继承现有仓库规范：分支、历史、worktree、文件预览/编辑和冲突处理。原型没有这些完整页面，不能据本交互表宣布已支持；真实文件保存需检查外部修改，变更后审阅证据失效。

## 8. 企业微信机器人与 WorkBuddy

### 8.1 设置页

| action | 入口 | 触发与成功表现 | 正式实现的边界/失败表现 |
| --- | --- | --- | --- |
| `robot-save` | 保存配置 | 校验机器人配置，保存并回读连接状态 | 原型仅内存；正式失败保留表单，不用“已绑定”代替测试 |
| `robot-demo` | 体验对话 → Work | 原型打开演示对话；正式可提供连接测试/查看对话，但不能发送未授权消息 | 关闭接收时演示入口提示原因；仅查看已有会话不受此限制 |

字段：机器人名称 1–50 个可见字符；启停控制新消息接收，既有 Work 保留；接收方式仅显示实际平台支持项；身份范围由接入侧校验。不能通过机器人名称判断发起人身份。

**工作目录自动识别为内建行为。没有群聊映射表、固定工作目录输入框、项目配置列表，也没有必须手选项目的创建表单。** 同群可讨论多个项目。未知目标在原聊天追问，不弹“去设置中配置目录”。

| action | 入口 | 触发与成功表现 | 正式实现的边界/失败表现 |
| --- | --- | --- | --- |
| `robot-preview` | 整理为 Work | 解析需求意图并识别项目；唯一时展示目标及已识别目录，歧义时在原对话发起澄清 | 当前原型仅名字匹配；正式无群聊默认目录，不把群名当权限 |
| `robot-directory-reply` | 回复并继续 | 将用户回答关联待澄清意图，重新判定唯一项目 | 不写群聊映射；空回答/仍多候选继续追问，不创建 Work；会话和发起人需匹配 |
| `robot-return` | 返回消息/返回修改/继续体验 | 返回来源对话草稿，保留本轮目标信息 | 新一条独立需求需重置澄清结果，不能沿用上个意图的目录 |
| `robot-create` | 确认创建 Work | 根据已解析 projectId 创建本地 Work、来源关联及排队记录；展示编号 | 幂等，同一来源事件只创建一次；目录失效不降级到其他项目 |
| `robot-open` | 打开项目 Work | 定位所创建 Work，展开其项目，显示对应会话与详情 | 无记录/不可访问提示，不默认打开最近 Work |
| `work-source` | 原始对话、来源卡片、查看结果回复 | 打开此 Work 的来源消息、澄清、创建回执及结果记录 | 不使用全局最后创建 Work；不跨账号/群显示消息 |
| `work-start` | 模拟启动 Work（正式“启动 Work”） | 排队或获得执行槽，创建工作树并启动 Run | 并发满排队，不越额；双击不双启动；原型定时变状态不复用 |

### 8.3 对话字段

- 原型的 `robot-chat` 只切演示对话来源，不配置项目；正式来源直接取收到的认证事件。
- `robot-request` 是原始需求，消息编辑/撤回保留事件版本；不随 UI 拼接后覆盖原文。
- `robot-directory-answer` 是对本次问题的回复，必须带意图/问题身份，不能应用到群里其他人的需求。
- `robot-work-title` 可编辑本地 Work 标题，澄清回复保持独立记录，不能变成标题的一部分。
- 已识别项目和规范化工作目录为只读结果；用户说“换到另一个项目”应重新解析和确认执行范围，而非改一行路径后复用旧授权。
- 原型确认卡用于评审。正式是否展示创建确认取决于意图和已有授权，不能把“自动识别目录”又变成必须手动配置。

### 8.4 Work 状态与汇报

创建后显示编号、项目、当前状态和原会话链接。待回答由 WorkBuddy 回到原对话；待审阅带摘要与链接；已完成可查看结果投递记录。发送失败显示失败，不用创建成功回执冒充交付结果。

独立 Work 不显示 TAPD 编号、排期或回填按钮。任务页可以保留通用 TAPD 导入入口，但当前 Work 的来源详情不得跳到无关需求。

## 10. 当前原型与正式行为的明确差异

1. 演示任务只在内存，部分普通会话也用 task 结构表示；正式必须分离 Work、Run、Session。
2. 演示 Git 文件/diff/验证为固定示例，Work 项目切换后不能认为它们是实际代码证据。
3. 演示“回填完成”可能同时把本地任务标为完成；正式分离接受结果与投递结果。
4. 演示收到业务确认后按计时器进入待审阅；正式依据执行事实和证据。
5. 演示机器人目录匹配不具备智能语义及本地目录访问能力；自动目录识别是需要实现的契约。
6. 展示型计数、连接和容量需接真实状态；不能把演示“已连接”用于正式上线。
7. 原型中部分静态设置、看板装饰和历史操作仅用于样式；正式逐项实现或取消交互外观。
8. 所有 action 的正式含义以本表及主文档为准，不能照搬当前 click handler 的副作用。
