# 企业微信多机器人、隔离续聊与决策卡片

本方案承接 [多 CLI 开发方案](DEVELOPMENT.md) 和 test 版原型。原型可配置多个模拟机器人，选择默认 CLI 并多选生效范围，演示不同人员、场景与项目的会话隔离，以及任务卡和拍板卡。正式连接、账号鉴权、会话持久化和企业微信端卡片回调需要单独验收。

## 1. 机器人配置与分流

| 配置 | 交互与行为 |
| --- | --- |
| 机器人列表 | 可新增、选择和启停。每个机器人有自己的名称、企业及 Bot ID、凭据引用、连接状态、对话模式和默认 CLI。新的机器人默认停用，尚未登记允许人员时不接收消息。 |
| 人员范围 | 可多选企业成员或角色组，以平台回调中的稳定成员 ID 匹配。可按角色区分普通使用者、任务发起者和拍板人。 |
| 场景范围 | 可同时选择私聊与多个指定群聊。配置群时绑定实际群 ID，并核对触发方式。群名只用于展示。 |
| 项目范围 | 可限定一个或多个登记项目。配置单项目时可默认使用该项目；多项目且意图不明确时，回复选择卡或在原会话追问。项目解析完成并授权通过后再读代码。 |
| 运行选择 | 「直接对话」可选择具备结构化执行能力的 CLI。「创建和跟进 Work」沿用独立的业务授权和执行队列。表单分别展示连接可用和引擎可用。 |

收到消息时先验证 Bot 和发送者。人员、会话场景、项目分别支持多选，同一项内命中任一值即可，三项须同时命中。每项可显式选择所有已授权对象，空集合一律拒绝。已有单选配置迁移为单项列表。没有明确权限、身份缺失或项目超出范围时停止路径，反馈所缺信息。按接收消息的 Bot 路由。同群登记多个 Bot 时，优先由被明确 @ 的 Bot 接收；多个规则可匹配同一无明确接收者的消息时，按产品拍板的冲突规则处理，避免多个 Bot 自动重复执行同一意图。

每个 Bot 使用独立连接与错误状态。现有实现收到 `disconnected_event` 会停止重连，避免同一组 Bot 凭据在两处反复顶替。多 Bot 沿用这一语义，每组凭据只由一个活动宿主持有。凭据按企业与 Bot 隔离存储，列表和日志只显示状态。 [现有连接及事件处理](../../Sources/ClaudeDeck/Work/WecomBot.swift)

## 2. 人员隔离、同步和续聊

- 会话归属键使用「企业／Bot／私聊或群聊／会话 ID／发送者 ID／项目 ID」。同群不同人员、同人不同群、私聊与群聊、不同项目和不同 Bot 都分别绑定。消息路由、摘要、审批、日志索引和通知一律携带该归属。会话记录另外保存 CLI 引擎、运行宿主、工作目录、原始会话 ID 和最近处理的消息位置。
- 首轮创建绑定，后续按原引擎和原始会话 ID 续接。机器人默认 CLI 只影响新绑定。换引擎、换项目或开启共享对话需要显式开启新绑定，保留原记录。原引擎不可用、原历史缺失或切换账号时提示恢复，未经用户确认不换引擎或开空白会话。
- 入站用企业、Bot 和企微消息 ID 去重。同一绑定串行处理，跨绑定可以并行。保存消息、回合状态、原始会话 ID、出站回执和消费进度；重连或 App 重启按未完成状态续跑。需要核实不确定的外部结果时，先查询已执行的回合或任务，再决定是否补发，避免重复创建任务。
- 桌面和机器人共享同一会话索引与事件游标。桌面按当前身份和项目权限读取，续聊沿用同一个原始会话，绑定内部只有一个写入者。桌面和企微先同步历史，再排队写入。企微回复只进对应 Bot 与对话的授权出站通道。群聊的上下文隔离和群内内容的可见范围是两件事；涉及私有项目和敏感上下文时，默认在授权私聊交付完整内容。
- 旧记录只有在能核实发送者和归属时才关联新绑定。缺少发送者的旧群记录保留为待归属，首条新消息创建独立绑定。机器人收发走企业微信自身连接。WorkBuddy 从机器人接入与设置页移除，仅在 CLI 引擎目录中登记，启动命令与结构化能力需验证后再开放。现有长连接消息可读取 `from.userid`，还需逐条核实既有存储、桌面读取和通知发送是否使用同一隔离键。 [现有企微消息入口](../../Sources/ClaudeDeck/Work/WecomBot.swift)

## 3. 选择卡与回执

官方 Python SDK 的 WebSocket 通道提供模板卡片回复、主动推送、卡片更新，以及 `event.template_card_event`。可以用它承载任务确认和业务选择。现有 Swift 机器人已处理消息和事件回调，在目前的事件分支中还需实现卡片事件处理及回执。真实租户要联调卡片类型、群内可见性、点击人身份、更新时限与失败降级。 [企业微信智能机器人官方 SDK](https://github.com/WecomTeam/wecom-aibot-python-sdk#-事件列表)

| 卡片 | 展示内容 | 可选操作和执行结果 |
| --- | --- | --- |
| 创建任务 | 标题、项目、来源、拟用引擎、目标与待确认信息 | 「确认创建」创建待执行 Work；「补充信息」回到发起人对应会话；「取消」关闭本次草稿。 |
| 待拍板 | 决策问题、选项、各项影响、负责拍板的人和有效期 | 「采用方案 A／B」「稍后决定」。答复写入原会话和关联 Work，已选择的卡片显示回执。 |
| 工具授权 | 由桌面结构化审批控件承载；企微可提醒待审批 | 企微任务卡和业务拍板卡仅处理业务选择。工具执行权限沿用 CLI 与桌面审批。 |

正式版为每张卡记录唯一 ID、绑定归属、业务对象、允许操作者、选项、版本与有效期。回调重新检查身份与权限、一致性、有效期及卡片版本。首次有效选择原子写入状态；重复点击返回已处理回执。过期、无权或任务已有更新时保留原状态，返回简短原因。回调时限内先接收或更新卡片，耗时工作异步处理，成功或失败回填到原归属。客户端或场景不支持卡片时，可回到原对话用带有效期的编号选项，使用同一套权限和去重规则。是否向群公开决策细节由产品规则决定。

## 4. 实施、验收和待拍板

| 阶段 | 验收条件 |
| --- | --- |
| A · Bot 配置与分流 | 两个机器人独立启停与配置；人员、群和项目可多选，任一项未授权则拒绝；同群双 Bot 无重复响应；同一 Bot 的凭据抢占行为保留。 |
| B · 持久化和同步 | 同群双人、同人跨项目／群／私聊均隔离；改默认 CLI 后旧会话不变；桌面、企微、App 重启后续聊原会话；重复回调和并发消息有序且不重复执行。 |
| C · 决策卡 | 真实企微私聊与群中验证卡片发送、指定人点击、重复点击、过期、不支持卡片时降级；创建任务默认等待执行，桌面与企微看到同一决定。 |

| 决策 | 建议起点 | 需要拍板 |
| --- | --- | --- |
| W1 · 生效范围 | 人员、场景、项目取交集。默认拒绝。群内优先显式 @ | 人员授权按成员或角色组；同群多 Bot 的冲突处理；是否开放显式共享上下文 |
| W2 · CLI 与历史 | 直接对话先接 Claude、Codex；Antigravity 通过 ACP 验证后开放；DeepSeek 等结构化协议和审批验证 | 各 Bot 是否允许发言人覆盖默认 CLI；引擎不可用时允许恢复、显式 fork，还是暂停 |
| W3 · 同步与可见范围 | 本地桌面为运行宿主，授权人读取自己的会话。群中仅回授权内容 | 是否跨设备同步、同步保留时间，以及管理员和项目成员可见范围 |
| W4 · 卡片授权 | 首版支持任务确认与业务拍板。卡片只接受指定身份，确认创建后等待执行 | 首发卡片类型、允许拍板的人员、卡片有效期、群可见性与不支持卡片时的交互 |

## 5. 开发分支实现

- 配置：`robot.bots` 保存 Bot 列表（名称、Bot ID、企业 ID、启停、模式、默认 CLI、范围）。没有列表时旧单 Bot 设置视为 `default`，范围迁移为「全部人员、全部会话、全部项目」，保持升级前行为；第一次在列表里保存时写入迁移结果。新 Bot 默认停用，启用前必须登记人员或选「全部人员」；同一 Bot ID 不能登记两次。
- 授权：先校验 Bot 与发送者，再校验场景（私聊开关、全部群或指定群 chatid），项目在理解意图后校验。任一项未命中直接回复原因，不读代码、不建会话或 Work。人员按 userid 匹配，角色组未实现。
- 续聊：绑定键为 `wecom.binding.<sha256(企业, Bot, 会话类型, 会话 ID, 发送人, 项目)>`。单项目 Bot 在该项目目录对话，多项目时在独立聊天目录对话并只列出授权项目。记录引擎、工作目录、原始会话 ID 与回执；默认 CLI 只影响新绑定。旧 `wecom.claude.*` 记录在归属可核实（同账户、会话、发送人）时沿用。
- 决策卡：直接对话中单个单选问题（2–6 个选项）推送 `button_interaction` 卡片，同时在文字回复里给出编号选项；卡片点击与编号回复共用一条记录，先到先得，非发起人、过期、无效选项不改状态，重复点击只更新卡片。Work 模式新建且等待启动的 Work 推送任务确认卡（确认、稍后决定、取消，取消会撤销该 Work）。卡片在回调 req_id 上 5 秒内用 `aibot_respond_update_msg` 更新，后续结果用 `aibot_send_msg` 回到原会话。
- 回归：`bash scripts/test-work.sh` 的企微段用本地 WebSocket 替身覆盖旧单 Bot 全流程、两个 Bot 独立连接与凭据、三项授权拒绝、同人同群跨 Bot 隔离、单项目绑定目录、拍板卡的无权点击、有效点击、重复点击与过期，以及单个 Bot 被顶替不影响另一个。真实租户联调见 [交接文档](HANDOFF.md#待验收与后续)。
- 拍板结果（2026-11-19）：W1 按应用内角色组授权（使用者 / 任务发起人 / 拍板人），同群同时 @ 多个机器人时按列表顺序只由第一个有权限的处理；W4 拍板卡 30 分钟、Work 确认卡 24 小时有效，群里完整显示。真实回调的卡片字段位于 `event.template_card_event` 下（与 SDK 类型定义的平铺写法不同），两种格式都兼容；最近一次卡片事件的字段结构记在设置 `robot.lastCardEvent` 便于排查（不含内容）。私聊场景已用真实机器人联调通过，见 [交接文档](HANDOFF.md#2026-11-19-桌面验收记录)。
- 第二轮真机联调（2026-11-19，两个真实机器人）：群聊回复、群聊与私聊按绑定分别续聊、群内拍板卡与点击、两个机器人独立连接、不接受私聊的机器人在私聊中拒绝均通过。企微对同时 @ 多个机器人的群消息会分别投递给各机器人，消息 ID 不同、到达间隔实测可达约 20 秒；裁决按「群 / 发送人 / 内容」去重，60 秒内迟到的回调沿用已有结果并回复由谁处理，不重复执行；「按列表顺序优先」只在 1.5 秒等待窗口内成立，是否拉长窗口待拍板。企微里的显示名与配置名不一定一致（本次「紫啧」对应 `default`、「曾长亮的机器人」对应第二个机器人），建议配置名与显示名保持一致。每个机器人最近 20 条入站元数据记在 `robot.inbound.<id>`（不含内容），用于确认消息是否到达与裁决结果。群内拍板人、非发起人点击需要第二位成员配合，尚未真机验证。
