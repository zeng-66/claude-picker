### 0.2 原则

1. **数据走真实桥接，不搬 mock。** 原型里的 `tapdTasks`、`workSeed`、`taskMeta`、`TerminalTranscript` 演示输出、`tapdCreatedWorks` 本地存储，一律换成现有 `tapd.*`、`work.*`、`session.*` 接口。原型只借布局和交互。
2. **能力不足时先隐藏，不做假按钮。** 原型里有、后端还没有的能力（TAPD 写评论、子需求等），列进 §14 待确认，确认前不显示。
3. **终端仍是原生视图。** macOS 的终端（SwiftTerm）或图形聊天（Swttch WKWebView）都通过「洞」机制（`data-terminal-hole` → `app.layout`）放置。悬浮终端显示内容时，只是把洞移到浮窗里，不在网页里重画终端。
4. **保留现有功能。** 原型没画出来的现有功能（Work 卡片菜单、项目筛选、加载更多、错误提示、只读实例提示等），默认保留并放进新布局，具体位置见各节。
5. **原型专用的东西不进正式版**：H5 批注组件、`?settings=updates` 参数、版本更新「原型场景」选择、桌面模式演示背景（见 Q14）。

### 0.3 不做的

- TAPD 只开放两种写操作：**发表评论**、**流转状态**。两者都需要用户在界面上明确点击（流转还要二次确认），不自动执行。创建 Work、Work 状态变化都不会改 TAPD。
- 流转时可同时修改处理人和该状态的必填字段（Q22 已确认）；除此之外不改 TAPD 的其它字段（迭代、优先级等）。
- 不改 Work 领域模型与 SQLite 结构。
- 不改 Swttch 上游（除已有补丁外）。

## 1. 整体布局与状态模型

### 1.1 窗口结构

```
┌ titlebar ───────────────────────────────────────────────────────────────┐
│ ● ● ●  │ [工作空间][TAPD 待办][Work 中心 ③][变更] │ (工作台页签区/拖动区) │ ⚙ │
├──────────────┬┬──────────────────────────────────────────────────────────┤
│ 第一栏        ││ 第二栏                                                    │
│ (Sidebar 或   ││ (终端 / TAPD / Work / Git 页面)                           │
│ ModuleSidebar)││                                          ┌─────────────┐  │
│              ││                                          │ 悬浮终端      │  │
│              ↔ 第一栏宽度拖动条                            └─────────────┘  │
│              ││                                                  🐾 桌宠  │
└──────────────┴┴──────────────────────────────────────────────────────────┘
```

| 当前页签 | 第一栏 | 第二栏 | 第三栏 |
| --- | --- | --- | --- |
| 工作空间 | `Sidebar`（项目 / 会话树、额度、添加目录、设置） | 选中会话的终端，或选中 Work 的 `WorkChat` | 可选：Git 工作台 / Work 上下文面板（同现状） |
| TAPD 待办 | `ModuleSidebar`：全部项目 + 已启用的 TAPD 项目 | TAPD 我的工作列表 / 工作项详情 | 无 |
| Work 中心 | `ModuleSidebar`：Work 分类 | 现有 Work 中心页面（§6.2） | 无 |
| 变更 | `ModuleSidebar`：分支搜索、分支选择器、五个 Git 页面 | 对应 Git 页面 | 无 |

### 1.2 新增状态

| 状态 | 含义 | 默认值 | 持久化位置 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | 当前顶部页签 | `workspace` | 网页 `useStored('page')` | 已存在，沿用 |
| `navigation` | `[{id, visible}]`，顺序即显示顺序 | 四个都显示，顺序为 工作空间 / TAPD / Work / 变更 | 原生 `settings.json`（Q15 已确认） | 新增 |
| `sections` | `{tapd: workspaceId 或 'all', works: 分类}` | `{tapd:'all', works:'all'}` | 网页 `useStored('moduleSections')` | 新增 |
| `tab` | 变更模块当前页面 | `工作区` | 网页 `useStored('tab')` | 已存在，沿用 |
| `sidebarWidths` | `{[page]: px}` | 空，每页默认 248 | 网页 `useStored('sidebarWidths')` | 新增 |
| `console` | 悬浮终端 `{minimized, size, position}` | 收起，360×214 | 网页 `useStored('consoleMinimized'/'consoleSize'/'consolePosition')` | 新增，替换旧 `floatingMinimized` / `floatingPosition` |
| `petSettings` | `{enabled, size, theme, idleShows, wander}` | `{true, 128, 'dev-life', true, false}` | 原生 `settings.json`（Q15 已确认） | 新增 |
| `petPosition` | 桌宠位置 | 右下角 | 原生 `settings.json` | 新增 |

存储键前缀：正式版沿用 `cp.`，不使用原型的 `cp.h5-v003.`。旧键 `floatingMinimized`、`floatingPosition` 启动时删除。

### 1.3 「终端实际可见」的定义

```
terminalVisible = page === 'workspace' && settings.terminal && !selectedWork
```

（原型没有 `!selectedWork`；现状选中 Work 时第二栏显示 `WorkChat` 而不是终端，所以要加上这个条件。）

- `terminalVisible` 为真：第二栏有洞，悬浮终端不渲染。
- `terminalVisible` 为假：悬浮终端可用（是否展开由 `console.minimized` 决定）。

### 1.4 页签可见性的边界规则

| 情况 | 行为 |
| --- | --- |
| 隐藏的正好是当前页签 | 切到剩余顺序里的第一个页签 |
| 只剩「工作空间」可见 | 不显示顶部页签栏，界面就是工作空间两栏 |
| 全部隐藏 | 不显示顶部页签栏；强制 `page=workspace`、清掉选中的 Work，并设置 `sidebar=true, terminal=true, workbench=false`（只在刚进入「全部隐藏」时执行一次）；设置入口仍可用 |
| 从桌宠 / 浮窗「在工作空间展开终端」，而工作空间页签被隐藏 | 有其它页签可见时，自动把工作空间设为可见；全部隐藏时不改 `navigation` |
| 「TAPD 创建任务」完成，而 Work 页签被隐藏 | 自动把 Work 设为可见再跳转 |

## 8. 悬浮终端 `FloatingConsole`

### 8.1 显示规则

- `terminalVisible` 为真时不渲染。
- 否则 `console.minimized=false` 时渲染浮窗；收起后不留任何图标，只能从桌宠重新打开（原型「入口融合」）。
- 桌宠被隐藏时，浮窗收起后显示小圆形浮标作为入口（Q13 已确认）：单击打开浮窗，可拖动，位置记忆到 `useStored('consoleBubble')`。

### 8.2 控件

| 控件 | 交互 |
| --- | --- |
| 标题栏 | 拖动移动（位移 > 4px 才算拖动）；位置限制在窗口内：左右各留 12px，上方留 52px（标题栏），下方留 64px |
| 标题文字 | 当前会话名，没有会话时显示「新对话」；执行中时显示「正在思考…」（沿用旧浮窗） |
| 展开 / 收起终端内容（ArrowsOut / ArrowsIn） | 小尺寸 → 设为 620×420；大尺寸 → 设为 360×214。两次都会按窗口重新限位 |
| 收起到桌宠（Minus） | `console.minimized=true` |
| 在工作空间展开终端（Terminal） | `restoreTerminal()`，浮窗随即消失 |
| 输入区 | 复用 `Composer`，发送走 `app.prompt`，与第二栏输入记录共用 |
| 右下角拖柄 | 拖动连续缩放；最小 280×180，最大受窗口限制；聚焦后方向键每次 ±20px |
| 左上角拖柄 | 反向缩放，同时移动位置，保持右下角不动 |
| 窗口尺寸变化 | 重新限位、重新限尺寸 |

### 8.3 显示终端内容（与原型不同的地方）

原型用 `TerminalTranscript` 画演示输出；正式版改为把终端「洞」搬进浮窗：

```
showOutput = size.width ≥ min(520, innerWidth-24) && size.height ≥ min(330, innerHeight-116)
```

- `showOutput` 为真：浮窗内容区渲染 `<div data-terminal-hole>`，原生把 SwiftTerm / 图形聊天视图对齐过去；标题栏的三个按钮和两个拖柄标为 `data-terminal-overlay`，保证洞上面的按钮仍可点击。
- `showOutput` 为假：只显示输入区，没有洞，原生终端视图隐藏。
- 浮窗与第二栏不会同时出现，所以页面上始终最多只有一个洞，原生侧不用改成支持多个洞。
- 浮窗移动或缩放期间每帧都在回报布局；需要确认原生 `applyLayout` 在拖动时不闪烁（§12 验收项）。
- Windows：`DesktopTerminal` 是网页组件，直接渲染在浮窗内容区即可。

### 9.8 实现要点

- 动画用 `<img>` 显示 APNG / GIF / SVG（WKWebView 均支持）。Dev Life 的眼睛跟随鼠标需要内联 SVG，P1 不做，P2 再评估。

- 设置与位置存原生 `settings.json`（Q15 已确认），为 P2 的原生窗口做准备。
- 授权：Clawd Dev Life 为 CC BY-NC-SA 4.0，ClaudePicker 只做非商业分发（Q27 已确认）；「关于」与桌宠设置的「素材署名」列出作者 alwinecor、仓库链接与授权，打包时附带 `LICENSE-ART`、`NOTICE.md`。
