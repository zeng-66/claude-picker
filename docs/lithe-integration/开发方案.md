# ClaudePicker → Lithe 开发方案

审核稿 · 2026-11-16

## 目标与审核基线

将 ClaudePicker 的会话管理、CLI 终端、配置、额度和偏好功能集成到 Lithe 工作台。Git 功能不在迁移范围。首期按 macOS 实现，Windows 作为后续平台适配。用户当前审核的是交互与实施方案，本文协议名称均为建议设计，须完成能力核查后确定。

原型位于 `prototype/index.html`，可直接用浏览器打开。所有会话、终端输出、额度、授权、导入均使用模拟数据，只把审核状态保存到浏览器 localStorage。

## 产品布局与操作规则

工作台保留文件编辑区。左侧新增 Claude 会话工具窗，项目下展示会话，底部或右侧打开宿主终端。原型使用终端主视图方便审核，会话区可收起，配置和额度用抽屉展开。

- 项目支持展开、搜索、添加目录、置顶、拖动排序与隐藏。
- 会话支持新建、恢复、置顶、拖动排序、隐藏。隐藏记录可通过管理入口恢复。
- 当前会话高亮。运行中展示动态状态，后台完成后出现未读点，选中时清除。
- 切换会话仅切换展示。关闭终端需确认终止进程，隐藏会话只影响列表。
- 跨项目打开先由宿主激活或打开目标工作区，再创建其拥有的终端。不得用任意绝对 cwd 绕过工作区约束。
- 达到 8 个句柄后展示终端管理，用户结束并释放一个句柄后重试。包括已退出句柄的回收策略须明确实现。
- 重启应用后保留会话索引和排列，再次点击通过 resume 恢复，旧进程状态不得假装仍在运行。

## 实现边界

### Claude 插件仓库

建议独立建立 `lithe-plugin-claude-sessions`，名称待审核。负责 Claude JSONL 解析、配置语义、CLI 能力探测、启动参数、状态信号识别、额度请求、旧状态解析及插件界面文案。使用项目支持的插件后端 SDK；后端语言在验证 SDK 与打包路径后定案，优先采用现有成熟工具链。

### Lithe 桌面宿主

复用 `desktop/internal/pluginservice/hostterminal.go`、`desktop/internal/workbench/terminals.go` 与已有 term / termview。负责终端显示、进程树回收、工作区路由、系统凭据接口、字体、快捷键及通用插件视图承载。沿用现有用户授权流程。

### 独立 Rust Core

先核查固定版本的插件契约。新增通用输入控制、终端事件、会话列表贡献或全局发现能力时，先在 Core 定义 schema、能力发现及 fixtures，再更新宿主与 SDK。Core 不解析 Claude 文件格式。

### 必须完成的能力验证

| 检查项 | 当前证据 | 验证后的处理 |
| --- | --- | --- |
| 原生树或面板贡献 | 本轮未确认完整契约 | 优先复用；缺失时增加通用列表/动作贡献能力 |
| 终端运行时输入 | 已读 TerminalSession 仅有 Show / Close / Done | 核查其他 API；缺失时新增受权限控制的输入能力 |
| OSC/输出/活动事件 | 未确认有插件订阅入口 | 核查事件源，新增限频、限量且可取消订阅 |
| 全局历史目录访问 | 现有终端工作区隔离已确认 | 核查文件授权和全局插件状态契约，显式声明读取范围 |
| 跨工作区路由 | 不能跨 workspace 使用句柄 | 返回目标工作区上下文后创建，句柄始终保留原归属 |
| 凭据与网络访问 | macOS 原实现调用 security | 核查插件能力与系统 keyring adapter，凭据不得回传界面 |

## 数据与异步状态设计

会话键由 provider + 规范化项目路径 + session ID 构成。项目路径只存在获授权的内部状态；传入 Core 的资源标识遵守现有工作区相对路径契约。符号链接规范化时保留用户展示路径。

建议内部记录包括 SessionRecord、TerminalBinding、TreePreferences 和 UsageSnapshot。字段须覆盖原 ID、项目、标题、摘要、时间、隐藏/置顶、状态、句柄、所属 context、generation 和更新时间。不要将临时终端句柄持久化为可恢复进程。

- 扫描状态为 idle → loading → ready / failed。重扫使用 generation 丢弃旧结果，文件变更合并处理。
- 终端状态为 stopped → starting → running / waiting / idle → stopping → exited，启动或控制失败进入 failed，状态未知时显示 unknown。
- 配置状态独立为 default、pending、applied、failed。CLI 未就绪时保留 pending，超时后显示重试，不伪报生效。
- 每次操作携带 operation ID、取消与超时。onExit 和主动关闭幂等，过期 generation 不得覆盖新启动结果。
- 文件扫描限制并发和内存，按需分页，超长行设置预算并产生诊断；尾部查找总结支持跨块完整行。大量历史时不可在 UI 主线程全量解析。

## 配置与旧数据迁移

读取 `~/.claude/settings.json` 前检查文件版本/元数据，写入只更新目标键，保留未知字段。串行化本插件写入，通过临时文件与原子替换提交；发现外部修改重新读取合并，有冲突则回读并提示用户选择，不能覆盖整份旧快照。

默认配置与运行时控制分开记账。模型切换后重新解析 effort 能力，fast 和权限模式按实际 CLI 版本探测。不得以固定延时作为会话已就绪的唯一条件。

导入先解析本地 picker tree.json，提供项目与会话数量、隐藏项及失效路径的预览。使用 schemaVersion、导入来源和文件指纹记录幂等标识。保存导入前插件偏好快照，撤销只回退本次导入产生的偏好。

## 失败与资源回收

| 场景 | 行为 |
| --- | --- |
| CLI 未安装或未登录 | 展示安装/登录指引和重新探测 |
| 项目目录缺失 | 保留历史记录，允许重新定位目录 |
| CLI 版本不支持选项 | 禁用对应动作并解释，其他会话可继续使用 |
| 窗口/工作区关闭 | 取消扫描和请求，停止其拥有的进程，撤销订阅并释放句柄 |
| 凭据被拒绝或额度接口变化 | 展示具体状态，保留会话功能，允许手动刷新 |
| 插件禁用/崩溃 | 宿主统一回收插件资源，重启插件后重新发现历史 |

日志不得包含 token、完整会话正文或用户键入内容。缓存、日志和导入快照写入平台可写目录，遵守 bundle 只读规则。
